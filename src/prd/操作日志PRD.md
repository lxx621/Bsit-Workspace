# 操作日志模块 PRD

> 模块路由: `/system/operation-record`  
> 所属: 系统管理  
> 权限操作: 查看(只读)

---

## 1. 功能概述

操作日志模块记录系统中所有用户的操作行为，包括API请求的详细信息。自动采集操作人、操作模块、功能名称、请求地址、请求方式、执行状态及耗时等数据，用于系统审计和问题追踪。

## 3. 数据结构设计

### 3.1 操作日志实体 (OperationRecord)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 主键ID |
| userId | Long | 操作人ID |
| username | String | 操作人账号 |
| nickname | String | 操作人名称 |
| module | String | 操作模块(如"用户管理") |
| description | String | 操作功能(如"分页查询用户") |
| url | String | 请求地址 |
| requestMethod | String | 请求方式(GET/POST等) |
| params | Text | 请求参数(JSON) |
| result | Text | 响应结果(JSON) |
| error | Text | 异常信息 |
| spendTime | Long | 耗时(毫秒) |
| status | Integer | 状态(0正常/1异常) |
| ip | String | 操作IP |
| createTime | DateTime | 操作时间 |

### 3.2 操作模块枚举(已知)
- 用户管理、角色管理、菜单管理
- 组织机构管理、字典管理、字典数据管理
- 文件上传下载、登录日志
- 角色菜单管理

### 3.3 API接口
| 接口 | 方法 | 路径 |
|------|------|------|
| 分页查询 | GET | /api/system/operation-record/page |
| 查看详情 | GET | /api/system/operation-record/{id} |
| 导出Excel | GET | /api/system/operation-record/export |

## 4. 逻辑功能设计

### 4.1 数据采集(后端AOP)
- 通过AOP切面自动拦截Controller方法
- 采集方法注解中的模块名和功能描述
- 记录请求参数、响应结果、执行耗时
- 异常情况记录error信息，status标记为异常

### 4.2 查看详情
- 点击"详情" → 请求完整记录 → Dialog展示
- 请求参数/响应结果以JSON格式化高亮显示
- 异常信息以红色文本展示

### 4.3 搜索与导出
- 与登录日志类似的搜索和导出逻辑
- 默认按操作时间倒序
- 导出包含搜索条件筛选的全部数据

### 4.4 性能考虑
- 数据量大(示例8579条)，必须后端分页
- 详情数据(params/result)不在列表查询中返回，仅详情接口返回
- 可考虑定期清理历史日志
